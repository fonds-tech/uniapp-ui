# Git 提交规范

## ⛔ 强制约束

**此技能只能执行以下操作：**

1. 使用 `git status`、`git diff`、`git log` 查看修改信息
2. 分析修改内容并生成提交信息
3. 使用 `git add` 和 `git commit` 执行提交

**绝对禁止：**

- ❌ 使用 Read 工具读取代码文件内容
- ❌ 使用 Edit/Write 工具修改任何代码文件
- ❌ 修复代码问题或调整代码顺序
- ❌ 执行任何与提交无关的操作

> 如果发现代码有问题，应该提示用户另行处理，而不是在此技能中修改。

---

## 使用方式

用户执行 `/git-commit` 时，按照以下流程生成提交日志。

---

## 执行步骤

### 1. 获取修改信息

```bash
git status          # 查看修改的文件
git diff --stat     # 查看修改统计
git diff            # 查看具体修改内容（如需要）
```

### 2. 分析修改类型

根据修改内容确定提交类型：

| 类型     | 说明     | 示例                   |
| -------- | -------- | ---------------------- |
| feat     | 新功能   | 新增页面、组件、API    |
| fix      | 修复 Bug | 修复逻辑错误、样式问题 |
| refactor | 重构     | 代码优化、结构调整     |
| style    | 样式     | CSS 调整、格式化       |
| docs     | 文档     | 注释、README           |
| chore    | 杂项     | 配置、依赖更新         |

### 3. 生成提交信息

**格式**：`<type>: <中文描述>`

**规则**：

- 描述使用中文
- 以动词开头（新增、修复、优化、调整、移除等）
- 简洁明确，不超过 50 字
- 不以句号结尾

---

## 提交信息示例

```bash
# 新功能
feat: 新增发票红冲功能
feat: 新增销售单搜索页面

# 修复
fix: 修复客户选项回显问题
fix: 修复表单验证逻辑错误

# 重构
refactor: 将多步骤表单拆分为独立组件
refactor: 优化列表页数据加载逻辑

# 样式
style: 统一按钮样式
style: 调整卡片间距和圆角

# 优化
perf: 优化分页加载性能
```

---

## 执行提交

1. 展示生成的提交信息给用户确认
2. 用户确认后执行：

```bash
git add <files>     # 添加指定文件
git commit -m "<提交信息>"
```

3. 提交后展示 `git log -1` 确认结果

---

## 注意事项

- 不要使用 `git add .` 或 `git add -A`，避免提交无关文件
- 敏感文件（.env、credentials）不应提交
- 如果修改涉及多个不相关功能，建议拆分提交
- 合并代码产生的 Merge commit 不需要修改
